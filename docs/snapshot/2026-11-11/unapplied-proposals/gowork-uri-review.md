# Windows GOWORK test URI identity proposal

Actual XML shows the primary assertion failure of all four cases is the Local target list string comparison (line152): expected URI contains literal 中文😀 while actual gopls URI UTF-8-percent-encodes these characters. The observed drive letter is C: on both sides. Local range is exactly (4,5)-(4,10). AUTO/EMPTY/ABSOLUTE each returned only provider/target.go at (2,5)-(2,13); OFF returned no sibling target. These facts do not make the complete tests PASS: assertions after the first failing comparison were not reached.

There is also an independent cleanup issue: EMPTY, ABSOLUTE and OFF record a Windows consumer-directory FileSystemException after two explicit owned-descendant destroy attempts each; AUTO records neither cleanup errors nor explicit signals. All four ownedRemaining lists are empty. The URI proposal does not resolve or hide this cleanup evidence.

The private one-file proposal preserves every original test identity and every later assertion. It replaces the two URI-string list comparisons with a shared exact-target assertion: exactly one response target; exact original UTF-16 Range; file scheme; expected and actual URI paths must both exist and resolve to the same `toRealPath()` result. No prefix/suffix matching, case folding, percent-string rewriting, target filtering or filename-only comparison. OFF retains its original empty cross-target assertion, and transport/failureKind checks remain. Real filesystem resolution occurs only in the already off-EDT fixture before its own cleanup. Raw protocol/evidence target URIs remain unchanged.

No production change, no main-tree or native-kit modification, no Gradle/Go/Java/GUI/remote operation. This proposal has not been compiled or run; actual Windows execution is required. Source HEAD C and all source pins stay frozen while root finishes native acceptance. Future integration changes the source digest and needs a new real verification/binding; do not reuse C-native evidence as proof of later bytes.
